# 2026-10-09 — charta-bridge：三个对局 bug（提交 `c14da0b`）

三条来自同一张牌桌的反馈，根子都在「在轮到的这一手」与「出牌人 actor」这对身份上——
明手让二者分离：`setCurrentPlayer(seat)` 里 `actorFor(seat)` 在 `seat == getDummySeat()`
时返回的是**庄家**。`playerAt(seat)`=轮到的那手，`currentPlayer`=actor。

## 1. 防家左下角显示「我方 0/11」

`BridgeScreen.renderPlayStatus`/`renderResult` 把 `menu.getRequiredTricks()`（**庄家的**所需墩数）
当分母给了双方。5 阶定约下防家读到 `ours 0/11`，而防家真正的目标是**击宕**：13−11+1=3。
- 抽 `localTarget()`：己方是庄家 → 返回 required；是防家 → 返回 `TRICKS - required + 1`。
- 判据 `declaringSide()` 用记分线已有的同余式 `floorMod(localSeat - declarerSeat, 2) == 0`。
- 流局（`required == 0`）退化为 13——没定约时唯一说得通的分母，此时 `declarerSeat=-1` 同余式也没意义。
- `renderResult` 同步改，并按 `getContract() == 0` 在 `progress_no_contract` / `progress` 间选文案。

## 2. 庄家能拿明手的牌给自己出牌

`canPlay` 原来接受 `getFullHand(player)` 里的任何牌，而它**折进了 carried slot**。
于是庄家从明手拎起一张、在自己**该出牌**时点它 → 过关；该墩把牌记到**庄家**座位，
牌却物理上离开了明手 → 明手整副牌少一张。
- 把 lifted 分支改成校验来源：拿 `liftedFrom(player)` 与「**轮到的那手** `playerAt(seat)`」比，
  来源不等于该手就拒。
- 顺手修一个四人桌才暴露的问题：来源原是单字段 `pickupOwner`，两人同时各拎一张会互相覆盖
  → 先拎的人**既出不了牌也放不回手**。换成按携带者索引的 `IdentityHashMap`
  （`BridgeBot.equals` 是歪的、实例又长命，故用恒等键）。
  - 写入：`HandSlot.onRemove`；清除：`HandSlot.onInsert` + 每墩开始（原 `pickupOwner = null` 两处）。
  - `canInsertCard` 同样读它，来源为 null（客户端镜像是不会跑 pickup 的）放行。

## 3. 双明手结果没在聊天栏播报

`table(line)` 只落进 Charta 的 `LOCAL_HISTORY`，而它**只被 `HistoryScreen` 渲染**，
BridgeBoard 又没暴露那个历史按钮 → 复盘等于不可见。
- `announceDoubleDummy` 末尾补 `player.sendMessage(line)`（= `displayClientMessage`，真·聊天行、
  读完还在），并对无服务端的调试牌桌补 `BridgeClient.chat(line)` 兜底
  （客户端玩家是 `AutoPlayer` 子类，`sendMessage` 是 no-op）。

## 验证

- `gradlew build` 成功（仅 3 条既有 `@Accessor` 警告）；`gradlew deploy` 成功，
  产物与 `build/libs` **逐字节一致**，无残留 `.staged`。
- 未 `runClient`（用户约定：只 build + deploy，自己跑）。

## NT 用 MC 正常字体 + 明手改为首攻后亮牌（提交 `0f8cecd`）

需求：「开局叫牌时的NT就用mc正常字体,不要拉伸」+「明手是在出完第一张牌之后再亮牌的」。

**NT 字体**：原来 NT 是私有区字形 `\uE000` + 自己的 13×12 贴图 `bridge:font/nt.png`。bitmap provider
按声明的 cell 高度栅格化、advance 由墨迹算 → 两个字母硬塞进一个花色 sprite 的框里，在 rank 数字旁边
就成了拉伸的糊。**改用普通字母 "NT"**：`bridge:suit` 没有 N/T 的 provider，会自动回退到 vanilla 字体，
大小/字重/基线都和旁边的数字一致。删掉 suit.json 里 nt.png 那条 provider（贴图留着、生成脚本也照旧写，
脚本头已注明"当前未用"）。`BridgeBid.glyph` 的 default 分支 `"\uE000"` → `"NT"`。

**明手亮牌**：`getCensoredHand` 原来 `phase != DEALING` 就翻开 → 整个叫牌阶段都亮着。桥牌里明手是**首攻后**
才摊牌的（在那之前防家是盲选）。加 `dummyExposed` 布尔：出本副第一张牌时置真、`startGame` 清零。
`AbstractCardMenu.broadcastChanges` 每 tick 拿槽位内容和上次发送的做 diff，标志一翻自己就同步，客户端零改动。
流局（`getDummySeat() == -1`）没有明手：保持暗牌、不播报。`message.bridge.dummy_is` 从叫牌结束挪到首攻那一刻
（原位置说"手牌摊开"其实还是背面）。

## 叫牌框改为下大上小 + 叫牌记录改为底行回卷（提交 `b496547`）

需求：「叫牌界面从上面最大变成下面最大,顺序颠倒,然后叫牌记录不论第一列从谁开始,只要最下面的叫完,就从第二列开始排」。

**叫牌框**：level 行原为顶=7、底=1。改成 `level = row + 1`（顶=1、底=7）。绘制与命中测试
（`callAt`）原来都写 `MAX_LEVEL - row`，两处一起改。

**叫牌记录**：原来一列 = 固定一轮 4 张，恒从顶行起、把每家放自己那行 → 庄家不在北时首列看着顶对齐、
和实际叫牌顺序脱节。改成**从首叫者（庄家）那行往下填**：首列从庄家行起、一到底行就结束，下一张开新列
回到顶行。于是首列按庄家靠下的程度变短、其后每列都是满的 —— 就是「最下面的叫完就换第二列」。
格子里的座位由填充规则定死，只需反推 call 下标；首列上方空格的判断就是"下标越界"。
表头改标列号，窗口仍钉在尾部（`auctionFirstRow`/`auctionColumnCount`/`auctionIndexAt` 三个小 helper）。

验证：`build` + `deploy` 成功、产物逐字节一致。
